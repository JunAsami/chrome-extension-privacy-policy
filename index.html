プライバシーポリシー

最終更新日: 2026年10月12日

Insight Plus（以下「本拡張機能」といいます）は、Yahoo! JAPAN ニュースコンソールの Insights ページを使う業務担当者向けの非公式ツールです。本プライバシーポリシーでは、本拡張機能が扱うデータと、その保存場所・送信先・使い道・消し方を説明します。

1. 収集するデータ

本拡張機能が扱うデータは、次のとおりです。

Insights ページから読み取るデータ

  • 記事の一覧（記事タイトル・記事ID・PV）
  • 記事の関連リンク（記事内の写真リンク・記事下の関連記事リンク）の位置・タイトル・URL・クリック数・表示回数・CTR と、取得した日時
  • 読み取りには、Insights ページ自身が使っている同じサイト内の API を、ユーザーがログインしている状態のまま使います。本拡張機能が Yahoo! JAPAN のログイン情報や Cookie を読み取ったり保存したりすることはありません

ユーザーが設定画面に入力するデータ

  • 媒体の情報、自動取得・自動差し替え・自動投入の条件などの設定
  • Google Apps Script の URL、Google Drive の送信先フォルダ
  • CTR.A の接続先 URL・API キー・Basic 認証のユーザー名とパスワード

媒体の WordPress 管理画面から読み取るデータ

  • 記事の関連リンク欄の今の内容、記事本文、予約投稿の一覧（タイトル・予約日時）
  • ユーザーがログインしている状態のまま読み取ります。WordPress のログイン情報は読み取らず、保存もしません

候補検索で受け取るデータ

  • 各媒体サイト・CTR.A・Google Apps Script から返ってくる記事のタイトル・URL・累計 CTR など
  • 媒体サイトの写真ページの写真キャプション

クリップボードの内容

  • ユーザーが「記事転記」「URL転記」「写真URL転記」「貼り付け」などのボタンを押したときだけ読み取ります

収集しないもの

  • 氏名・メールアドレス・住所などの個人情報
  • 閲覧履歴、位置情報、キー入力やクリックの記録
  • 利用状況の分析・テレメトリのためのデータ（分析ツールは組み込んでいません）

2. データの保存場所と送信先

重要： データは、お使いのブラウザのローカルストレージ（chrome.storage.local）に保存します。次の 2-2 に書いた場合に限り、書いた条件のときにだけ、端末の外へ送ります。

2-1. ブラウザのローカルストレージ

Google アカウントとの同期はしません。保存するものは次のとおりです。

  • 媒体ごとのセッションと CTR データ（記事タイトル、関連リンクのタイトル・URL・CTR、取得日時など）
  • 調整ツールの配置・ストック・候補・検索結果、事前準備のストック、完了した記事の記録
  • 設定（媒体の情報、各種の条件、Google Apps Script の URL、Google Drive の送信先、CTR.A の URL・API キー・認証情報）
  • 自動取得の状態、検索結果の短時間のキャッシュ、送れなかった調整履歴の再送待ち
  • WordPress から読んだ記事本文

2-2. 端末の外へ送るもの（送信先ごと）

(1) Google Apps Script 経由で Google Drive へ（調整履歴）

  • 条件: 設定画面で、その媒体の Google Apps Script の URL と Google Drive の送信先フォルダを設定しているときだけ送ります。設定していなければ送りません
  • 送るとき: 調整ツールで記事を「完了」にしたとき（自動差し替えの条件を満たして自動で完了した場合を含みます）。送れなかった分は、次に調整ツールを開いたときに自動で送り直します
  • 送るもの:
    • 調整履歴（JSON ファイル）: 媒体、記事ID、記事タイトル、完了日時、達成した条件、本拡張機能のバージョン、配置・ストックしたリンクのタイトル・URL・CTR の予測値、そしてその記事で取得した CTR データすべて（取得日時、位置ごとのタイトル・URL・CTR・クリック数・表示回数・PV・1分あたりの PV）
    • 週ごとのまとめ（Markdown ファイル。週ごとの送信先フォルダを設定しているときだけ）: 記事タイトル・記事ID・完了日時・達成した条件、採用したリンクのタイトル・URL・CTR の予測値

(2) Google Apps Script 経由で Google スプレッドシートへ（投入の記録）

  • 条件: その媒体の Google Apps Script の URL を設定しているときだけ送ります（Google Drive の送信先を設定していなくても送ります）
  • 送るとき: 調整ツールで「投入」したとき（自動投入を有効にしている場合は自動で）
  • 送るもの: 日時、媒体、記事タイトル、配置したリンクのタイトル・URL・候補の出どころ。CTR の数値は送りません
  • 保存先: Google Apps Script に設定されたスプレッドシートの「assembler_log」シートに 1 行ずつ追記されます

(3) Google Apps Script での調整履歴の検索

  • 送るとき: 候補検索で調整履歴を検索したとき（調整ツールで自動検索を有効にしている場合は自動で）
  • 送るもの: 検索キーワード（記事タイトルから作った語）と媒体の種別。管理者向けの評価画面では記事タイトルも送ります
  • 受け取るもの: 過去の調整履歴にある記事のタイトル・URL・累計 CTR など

(1)〜(3) の送信先について: Google Apps Script・Google Drive・Google スプレッドシートは Google のサービスです。送ったデータは、設定した Google Apps Script を管理する人の Google アカウントにあるスプレッドシートと、設定画面で指定した Google Drive のフォルダに保存されます。チームで共有の Google Apps Script の URL を使っている場合は、そのスクリプトの管理者（開発者が管理している場合は開発者）がデータを見られます。また、Google Apps Script の実行ログに、送った内容の一部（ファイル名や先頭の文字列）が残ることがあります。

(4) 媒体の WordPress 管理画面（https://kbs-yftp.kobunsha.cloud/wp-admin/）

  • 送るとき: 調整ツールで「投入」したとき（自動投入を有効にしている場合は自動で）
  • 書き込むもの: 記事の関連リンク欄に、配置したリンクのタイトル・URL を入力します。自動投入で「投入後に自動でWP更新」を有効にしている場合は本拡張機能が「更新」ボタンを押して保存し、それ以外はユーザーが自分で更新します。完了済みの記事では「関連記事を本サイトへ出力」の欄にチェックを入れます。CTR の数値は書き込みません
  • そのほかの通信: 記事タイトルでの記事の検索（記事タイトルを送ります）、編集画面と予約投稿一覧の読み取り、本拡張機能が開いた編集画面の編集ロックの解除
  • 認証: ユーザーがブラウザで WordPress にログインしている状態のまま、そのユーザーの権限で動きます。WordPress のログイン情報は読み取らず、保存もしません

(5) CTR.A（https://bravoworks.jp）

  • 条件: 設定画面で CTR.A の API キーと Basic 認証の情報を入れているときだけ送ります
  • 送るとき: 候補検索の「CTR.A検索」、調整ツールの統合検索（自動検索を有効にしている場合は自動で）、設定画面の「接続テスト」
  • 送るもの: 検索条件（媒体、キーワード、除外する語、CTR の範囲、並び順、ジャンル、件数）と、認証のための API キー・Basic 認証のユーザー名とパスワード
  • 読み取りのみで、書き込みはしません

(6) 各媒体サイト（https://jisin.jp 、https://smart-flash.jp 、https://www.jiji.com ）

  • 送るとき: 候補検索・調整ツールで関連記事の候補を探すとき、写真のキャプションを読むとき
  • 送るもの: 検索キーワード（記事タイトルから作った語）。ほかに、写真ページの内容やリンクの転送先を確かめるため、公開されている記事ページの URL に GET でアクセスします
  • Cookie は送りません。読み取りのみで、書き込みはしません

(7) ローカル LLM（Ollama、http://127.0.0.1:11434）

  • 同じ PC の中で動くプログラムへの通信で、データは端末の外には出ません
  • 送るもの: 記事タイトル、記事本文（設定に応じて冒頭の一部または全文。最大 20,000 字）、指示文。CTR の数値は送りません
  • 条件: 管理者向けの機能です。管理者が設定画面で接続を許可したとき（任意の権限）だけ使います

Insights ページについて: Insights ページのデータは、ページ自身の API にログイン中の状態のまま問い合わせて読み取ります。このとき送るのは、媒体・記事ID・集計期間の指定だけです。

2-3. 端末の外へ送らないもの

  • 完了にしていない記事のセッションと CTR データ、Google Drive の送信先を設定していない媒体の CTR データ
  • 自動取得・自動差し替えの条件などの設定、媒体の情報
  • WordPress から読んだ記事本文と予約投稿の一覧（ローカル LLM に渡すときも同じ PC の中だけです）
  • クリップボードから読んだ内容（取り込んだリンクを配置して投入した場合は、2-2 の (2)(4) のとおり送ります）
  • Yahoo! JAPAN と WordPress のログイン情報（本拡張機能は読み取りません）

ユーザーがデータをエクスポートした場合、ファイルはユーザーの PC に保存されます。ポップアップのバックアップにはセッションと CTR データが入ります。設定画面の「全設定エクスポート」には設定が入り、CTR.A の API キー・Basic 認証のパスワードと Google Apps Script の URL も含まれます。事前準備のストックのエクスポートには、配信前の記事タイトルが入ります。いずれもファイルの扱いに注意してください。

3. データの使用目的

データは、次の業務のためだけに使います。

  1. Insights ページから記事ごとの関連リンクの CTR を取得する（手動・自動取得タイマー）
  2. 記事ごとのセッションに CTR の推移を記録し、位置ごとに CTR の高いリンクの配置を計算する
  3. 差し替え候補の記事を、媒体サイト・CTR.A・過去の調整履歴から探す
  4. 調整ツールで関連リンクの配置を決め、媒体の WordPress 管理画面の関連リンク欄に反映する
  5. 完了した記事の調整履歴を Google Drive・スプレッドシートに残し、次の調整に使う

4. データの共有

  • データを販売しません
  • 2-2 に書いた送信先のほかに、データを第三者へ渡しません
  • 分析・広告・テレメトリのためにデータを送ることはありません
  • 信用力の判断や融資の目的でデータを使ったり渡したりしません
  • 3 に書いた目的と関係のない目的でデータを使ったり渡したりしません

5. 使用する権限

本拡張機能は、以下の権限を使用します：

  • clipboardRead: ユーザーがボタンを押したときだけクリップボードを読み、コピーした記事タイトル・URL の一覧を候補リスト・最適配置の欄・ストックに取り込むため。読んだ内容はローカルに保存するだけです
  • clipboardWrite: CTR の取得が終わったとき（自動取得の完了時を含みます）に、記事タイトルまたは記事IDを自動でコピーするため。投入する関連リンクの一覧のコピーと、各画面のコピーボタンにも使います
  • storage: セッション・CTR データ・設定などを、ブラウザのローカルストレージ（chrome.storage.local）に保存するため
  • alarms: ユーザーが指定した間隔・回数で CTR を繰り返し取得する自動取得タイマー（データ自動取得・データ自動全取得）のため
  • notifications: 自動取得の完了、WordPress で記事を更新した後に CTR 監視タイマーを始められなかったこと、関連リンク欄が書き換わっていたため自動投入を止めたこと、投入しなかった欄が書き換わっていたことを、デスクトップ通知で知らせるため
  • offscreen: タブが裏にあっても通知音を鳴らすため。また、設定で有効にしたときだけ、WordPress 編集画面の HTML から記事本文の段落を読み取るため
  • tabs: 本拡張機能の画面（調整ツール・設定画面）が開いているタブを探して前面に出す・重複したタブを閉じるため。Insights ページと WordPress 管理画面のタブを探して、取得や投入の指示を送るためにも使います。閲覧履歴を記録したり送ったりはしません
  • scripting: 媒体の WordPress 管理画面で、記事タイトルに一致する記事の編集画面へのリンクを探すため、また開いた編集画面が有効か（投稿が削除されていないか）を確かめるため。ページを読むだけで、書き換えません

ホスト権限

  • https://console-news.yahoo.co.jp/insights/news/*: Insights ページの記事一覧に CTR 取得のボタンや合計 CTR の列を追加し、ページが使っている同じサイト内の API から関連リンクの CTR を読み取るため
  • https://bravoworks.jp/*: CTR.A で過去に CTR の高かった記事を検索するため（検索条件と、ユーザーが設定した API キー・認証情報を送ります。読み取りのみ）
  • https://script.google.com/*、https://script.googleusercontent.com/*: ユーザーが設定した Google Apps Script で、調整履歴の検索（読み取り）と、調整履歴の Google Drive への保存・投入の記録のスプレッドシートへの追記（書き込み）を行うため
  • https://jisin.jp/*、https://smart-flash.jp/*、https://www.jiji.com/*: 各媒体サイトで関連記事の候補を検索し、記事のタイトル・URL・写真のキャプションを読むため（読み取りのみ。Cookie は送りません）
  • https://kbs-yftp.kobunsha.cloud/wp-admin/*: 媒体の WordPress 管理画面で、調整ツールで決めた関連リンクを関連リンク欄に入力して更新するため。今の配置・記事本文・予約投稿の一覧を読み、本拡張機能が開いた編集画面の編集ロックを解除するためにも使います（ログイン中のユーザーの権限で動き、ログイン情報は読みません）

任意の権限

  • http://127.0.0.1:11434/*: 同じ PC で動くローカル LLM（Ollama）に記事タイトル・本文を渡し、検索キーワードを抜き出すため。管理者が設定画面で許可したときだけ使い、端末の外には送りません

6. データの保存期間

ローカルのデータ

ユーザーが削除するか、本拡張機能をアンインストールするまで保存します。ただし、次のものは自動で消えます。

  • 調整履歴の検索結果のキャッシュ: 5 分
  • 送れなかった調整履歴の再送待ち: 最大 5 回送り直し、それでも送れなければ破棄します
  • WordPress から読んだ記事本文: 媒体ごとに新しい順に 60 本、合計 200,000 字まで。超えた分は古いものから消します

送信先に送ったデータ

  • Google Drive のファイル、スプレッドシートの行、WordPress の関連リンク欄に入れた内容は、それぞれのサービスに残ります。保存期間は、各サービスとその管理者の運用によります
  • CTR.A と各媒体サイトに送った検索条件をサーバー側でどう扱うかは、それぞれの運営者によります

7. データの削除

ローカルのデータ

  • ポップアップの「全媒体リセット」ボタン: 全媒体のセッションと CTR データを削除します（取り消せません）。設定は削除されません
  • 設定画面で入力した値（Google Apps Script の URL、Google Drive の送信先、CTR.A の API キー・認証情報など）: 設定画面で欄を空にして保存すると削除されます
  • 本拡張機能をアンインストールすると、ローカルに保存したすべてのデータが削除されます
  • エクスポートしたファイルはユーザーの PC にあるため、ユーザーが削除してください

送信先に送ったデータ

本拡張機能の操作やアンインストールでは削除されません。それぞれのサービスで、アカウント・サイトの管理者が削除してください。

  • Google Drive: 送信先フォルダの調整履歴の JSON ファイル・週ごとの Markdown ファイル
  • Google スプレッドシート: 「assembler_log」シートの行
  • WordPress: 記事の関連リンク欄に入力した内容

8. セキュリティ

  • データはユーザーのブラウザのローカルストレージに保存します。CTR.A の API キー・Basic 認証のパスワードも、暗号化せずにそのまま保存します。共有の PC では、使い終わったら設定画面で削除してください
  • ホスト権限で許可している外部の送信先はすべて HTTPS です。ローカル LLM への接続は、同じ PC の中（http://127.0.0.1）だけです
  • Yahoo! JAPAN と WordPress のログイン情報・Cookie を読み取ったり保存したりしません。各媒体サイトへの通信には Cookie を付けません
  • リモートコードは使いません。外部のスクリプトを読み込んだり実行したりせず、使っているライブラリ（kuromoji・Chart.js）とその辞書は本拡張機能に同梱しています

9. 対象ユーザー

本拡張機能は、Yahoo! JAPAN ニュースコンソールの Insights ページを業務で使う担当者向けに設計されています。一般の利用者向けの拡張機能ではありません。

10. 免責事項

本拡張機能は、Yahoo! JAPAN ニュースコンソールを使用するユーザー向けの非公式ツールです。Yahoo! JAPANとは一切関係がありません。本拡張機能の使用は、Yahoo! JAPANの利用規約に従って行ってください。連携する WordPress・Google のサービス・CTR.A についても、それぞれの規約や運用ルールに従ってください。

11. プライバシーポリシーの変更

本プライバシーポリシーは、必要に応じて更新される場合があります。送るデータや送信先を変えるときは、このページを更新し、最終更新日を改めます。
